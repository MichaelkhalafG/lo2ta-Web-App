## Part 7.1: staff and safety

Built (choices D74-D78 in PLAN 2.7):
- Staff (admin only): the list with each person's role, state, last sign-in and a history drawn as a revision block;
  invite by link (G14); edit name, role, e-mail language, switch on or off; send a password link (G13). No one can
  switch off or demote themselves or the last active admin. Accounts are never deleted.
- Set-password link page (signed out): one use, 60 minutes, only the token's sha256 stored, one neutral message for a
  wrong, used or expired link, ten bad links an hour pause an address. Using it lifts a staff sign-in lock.
- My account (every staff member): own details and a password change with the current password; five wrong tries in
  ten minutes pause it.
- A new password signs that person out everywhere (a mark of the password hash in each session); their own session
  stays signed in after changing it themselves.
- Two e-mails (Arabic and English, ours for the client to review): staff invite and staff password link; the staff
  sign-in-lock e-mail now points to an admin's link instead of "the password can be changed".
- Shared review components for the next parts: revision block, state badge, reason dialog.
- Security tests: every signed-in dashboard route needs the admin guard, the active-account check and a `can:`
  ability unless it is one of the four open to both roles; a reviewer gets 403 on every admin-only screen; every model
  either logs itself or names the log lines that cover it.
